# Map coverage (phase K0)

What stands between each original map and full playability, so the rest of phase K is ordered by data. Regenerate with

```sh
.venv/bin/python -m engine coverage            # out/coverage.csv (map x feature, gitignored) and the block below
```

The block between the markers is generated; the text before and after it is written by hand (K0, 2026-11-09) and quotes the numbers of that run.
Code and the status table: `engine/coverage.py` (`FEATURES`, `STEPS`; the trigger kinds are probed from the trigger code itself). Tests:
`tests/test_engine_coverage.py`. A K step that builds a feature flips its status in `engine/coverage.py` in the same change and ends by running the
command (CLAUDE.md, session routine).

**How a map is judged.** The scan reads only the map data: the check / instant / group kinds that an *active trigger reaches*, the usable structures
(`Usable` in structures.reg, split by editor name), the structures a script reads (check 21, instant 26), the quest items a check waits for that a
monster carries or a sack holds, the spells on unit types and items, shooters, casters, flyers, music zones. A feature is a **blocker** only where the
data shows the mission's goal passes through it (checked by hand for the ones found: the quest-item triggers feed the variables that end the mission,
the switch checks are the puzzle of maps 93-96 and 103, a signpost instant is always a message). The smoke run (1600 ticks, script and AI, no player)
adds what the engine itself reports. It found one crash (map 96, a cast at a 2 x 2 target; fixed in the same commit, `tests/test_engine_spells_cast.py`).

Scanned 46 campaign maps; smoke run 1600 ticks of the map script and the AI with no player.

**46 of 46 maps have no known blocker** (46 playable now, 0 with gameplay gaps), 0 are blocked. This is an upper bound: it means no feature in the list below stops the mission and the smoke run did not crash, not that the map has been played.

- **blocker**: the mission cannot be completed as designed (a script variable that gates the goal is fed by an action the engine cannot do).
- **gameplay gap**: content the engine ignores but the goal does not depend on (a usable well, a spell duration).
- **polish**: simulated but not drawn or played (arrows, status effects, music).

## Proposal and comparison with docs/prototype.md (K0, 2026-11-09)

**Finding.** The script engine is almost complete: of the 55 script kinds the 46 maps use (18 checks, 29 instants, 8 group commands), only check 25 (Spell on Tile) and the instants 29 / 30 (spell
durations) are counted no-ops; variable references and unit names are used by no map; every spell found on a unit or an item has a handler; casters,
shooters, flyers and ghosts all run. What blocks maps is **player actions the engine cannot issue**: picking an item up by click (7 maps whose
mission variables are fed by a quest item) and using a structure (the switch puzzles of 5 maps, 3 of which also read check 25). Everything else is
drawing, sound and shell.

**Proposed order** (the table above, numbered as the next K steps; effort is an estimate):

| Step | Name | Effort | Maps newly playable | Playable after |
|---|---|---|---|---|
| K5 | `pickup`: the pickup cursor issues `PickUp` (the simulation side exists), quest items reach the pack | 1 | 7 (21, 40, 63, 72, 80, 91, 102) | 41 of 46 |
| K6 | `use`: command `0x24`, the use order (state `0xf`), the switch state that check 21 reads | 3 | 2 (96, 103) | 43 |
| K7 | `tilefx`: check 25 reads the cell layers, instants 29 / 30 set spell durations | 1 | 3 (93, 94, 95: they need K6 as well) | 46 |
| K8 | `use_more`: signpost messages, wells, King's graves, altars (research each class) | 2 | gameplay only (33 maps touch a usable structure) | 46 |

**K8 done (2026-11-09):** wells, signposts and graves are built ([structures §0](engine/structures.md)); the 33 maps that contain one run the use of every such structure in `tests/test_engine_structures_k8.py`; the regenerated block reads 46 of 46 playable now, 0 with gameplay gaps.

| K9 | `draw`: status effects of units, arrows of shooters | 2 | polish only (46 maps) | 46 |
| then | `sound`, `hero_ui`, `menus`, `save`, `campaign` | 5 + 3 + 4 + 4 + 8 | none: no map needs them to be completed | 46 |

**K9 done (2026-11-09):** the shooters' arrows, bolts, stones and the Sonic lens, the one-shot Teleport / Drain Life sprites and the spell missiles' start (ShootOffset, altitude 0) are drawn from the client projectile model of the exe; the **status effects need no drawing** (CONFIRMED: the exe's hit sprites live 0 steps, only Invisibility and Stone Curse change a unit, no panel icon): [rendering.md "Arrows and shots"](engine/rendering.md#arrows-and-shots-k9) and [Status effects](engine/rendering.md#status-effects-k9). The regenerated block reads 46 of 46 playable, no polish gap left but sound.

**K5 done (2026-11-09):** the pickup click and the pack-based script items are built ([items](engine/items.md)); the regenerated block above reads 41 of 46 maps without a blocker (12 playable now), as predicted.

K5, K6 and K7 together unblock all 12 blocked maps; K5 and K7 are one small step each, K6 is the only research-heavy blocker (the use order and the
switch class are only partly read: command `0x24` in [click-to-move-research](engine/click-to-move-research.md), state `0xf` in [unit-struct](engine/unit-struct.md)).

**Against the backlog of [prototype.md](prototype.md#phase-k-backlog-by-value)** (listed there by value, not by data):

| Backlog item | Data says |
|---|---|
| 1. Inventory and hero windows | Split. The **pickup click** is the cheapest, most valuable step (K5, 7 maps). The hero windows block no map (the pack window and the info panel exist): they move behind the blockers. |
| 2. More spells | Effect drawing and arrows: done (K9). Structure targets: no map or AI needs them. The spell durations belong to K7. |
| 3. Full triggers | Almost nothing left: check 25 and instants 29 / 30 (K7). Variable references 8000-9999 and unit names >= 11001 are used by no map: drop them. |
| 4. Campaign | Blocks no single map (the party of a map is placed fresh, [triggers §9](engine/triggers.md#9-the-party-at-map-start-fun_004f2c83)); it is the largest step and gates a finished game, not a playable map. |
| 5. Full UI | Same: shell, not map content. |
| 6. Sound and music | Every map has music zones; polish. |
| 7. Save / load | Not a map blocker. |
| **missing** | **Use a structure** is not in the backlog at all, yet 5 maps are blocked on it (K6) and 33 maps contain a usable structure (K8). |

**What the report does not know.** The effort figures are estimates. The behaviour of wells, graves and altars was researched in K6 / K8 ([structures](engine/structures.md)). The verdicts are an upper bound: a map without a listed blocker may still fail
for a reason the scan cannot see (a balance problem, a bug in a path of the engine no test covers), which only a play-through shows; map 32 is the one
prepared for it ([prototype.md](prototype.md)). The idle party is lost within 100 s on six maps (43, 60, 70, 92, 102, 110); with a fresh level-1 party and
nothing ordered this may be the original's behaviour too, but it was not compared.
