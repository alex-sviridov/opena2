## 5. Edge scrolling and keys

- Per game tick (`FUN_00488aa1`; variants `FUN_00488900`, `FUN_00488e25`), in game state 1 and when mouse-manager
  field `+0x9c == 0` (`FUN_0041e730` = `mov eax,[ecx+0x9c]`; the manager is the global `0x604500`; meaning in 5.1): mouse x == 0 -> x velocity -1
  (`FUN_00403f4f`), y == 0 -> y -1 (`FUN_00403fc5`), x >= W-2 -> +1, y >= H-2 -> +1. **The test is on the screen
  border only; panels do not matter** (x >= W-2 lies over the right column). The view applies the velocity at
  `0x407067` and zeroes it after the draw (`0x40aefd`): **one whole cell per tick** (32 px x 16 ticks/s = 512 px/s
  at the default speed), diagonal when both axes trigger, clamped to the camera range. CONFIRMED.
- Arrow keys (`FUN_0040c8a0`, VK 0x25-0x28) add the same +-1 velocity. CONFIRMED.
- The cursor chooser `FUN_0040b2b8` uses the same thresholds for the arrow cursors (section 6).

### 5.1 The mouse manager's left-button capture (`+0x9c`) (CONFIRMED)

`+0x9c` of the mouse manager (global `0x604500`) is the **left-button capture flag of a press in the world** (the selection drag), not a modal or
a general mouse grab. **Set** only by `FUN_0042748f(point)` (`0x40c4ae`, left press in the view, state 1, no capture yet, `view+0x80 != 0`): `+0x9c = 1`,
the drag rect at `+0x6c` (`SetRect`: press point twice), the tooltip dropped (`+0x60 := 0`, `FUN_00427e45`), the rubber band drawn (`FUN_0042754f`);
`FUN_0048acbc` clips the pointer to the view rect first. **Cleared** by `FUN_00427501` (erase the band `FUN_0042772f`, `+0x9c = 0`, tooltip clock restarted),
always followed by `FUN_0048ad61` (`ClipCursor` back to the saved screen rect `client+0x5dc`). Callers of the clear (`+0x9c` readers, all `if (+0x9c)`):

| caller | event | then |
|---|---|---|
| `0x40c5d1` | left release in the view | `FUN_0040b2b8` cursor, `FUN_004175c7` selection / order ([research 1.2](click-to-move-research.md)) |
| `0x40c2d4`, `0x40c34d` | other view paths (research row) | as a release |
| `0x40c1d0` messages `0x40e` / `0x40f` | the inventory / spell book bar toggles (I, B, Q, Space, buttons) | a **release is dispatched** at the pointer: clear, cursor, `FUN_004175c7` |
| `0x48aea8`, `0x48b885`, `0x48b1f9`, `0x48b33b` | mission won / lost, a pause or text dialog opens | clear only: **no release**, nothing selected or ordered |
| `0x4a37f3` / `0x4a3a1d` (pack), `0x4c77a2` (book move) | callers test `+0x9c` (the book move: clear, CONFIRMED in 11.12; the pack pair INFERRED the same) | the pointer is over those bars: clear |
| `0x4ab6d4` (vtable `0x5cede0`, the right column window 4) | `WM_MOUSEMOVE` over the column | clear (only reachable if the clip failed) |

Effects while `+0x9c != 0`: (1) **no edge scroll** (`FUN_00488aa1` and its two variants); the arrow keys still scroll; (2) **the cursor chooser**
(`0x40b57f`, `0x40bab4`, on `[0x604500]+0x9c != 0` and `IsRectEmpty(normalised drag rect) == 0`) shows **default** (`0x626cb8`), over the pending-mode and the plain branch (not
the open-book cast branch), after the border arrows and before the open-dialog / carried-item overrides; an empty rect (pointer on the press x or y) keeps the real cursor;
(3) a second left press does not begin another capture (the `0x40c4ae` test) and no tooltip shows (the show rule, 11.6b); (4) **rubber band**: `FUN_00426594` (every pointer move) erases (`FUN_0042772f`),
sets the rect's far corner to the pointer, redraws (`FUN_0042754f`): a **white 1 px rectangle** on the screen surface, `FUN_004569a3(l, t, r-1, b-1)` of the normalised rect, colour = all bits of the pixel format (`0xffff`), restore strips saved by the erase.
Not affected: the minimap, panels and bar buttons are other windows whose presses never set `+0x9c` (so the edge scroll continues during a minimap drag), the right button, the arrows.
**Engine:** `SelectionInput.corner` is the capture (set by a world press, cleared by the release and, as a DECISION, while a dialog is frozen; the bars toggled by a key mid-drag do not dispatch the release, not built);
`ScrollInput.update(captured=)`, `CursorInput.dragging` (`choose_cursor` default), the white band (`selection.band_lines`, drawn after the frame, before the cursor), and the pointer clipped to the view
for the band and the release (`selection.clip_to`; DECISION: the exe's clip rect is the view rect with the bottom raised to the top of an open bar, `FUN_0048acbc`, not reproduced). Tests in `tests/test_engine_layout.py`.

## 7. Picking

- The view draw registers one **screen rect per drawn object** (`FUN_00404d99`, `0x408713`-`0x4087df`; `view+0x134`
  = count) while the object's death stage is `< 2`: the type's `SelectionX1/Y1/X2/Y2` offset by
  `(obj+0x64 - CenterX, obj+0x68 - CenterY - obj+0x6c - obj+0x10)` (screen position of the sprite anchor, minus
  ground height `Z`, minus flyer altitude). CONFIRMED ([units](../formats/units.md)).
- `FUN_004180c6` (hover, every frame): the mouse box `(x-1, y-1, x+1, y+1)`; the rects are walked from the **last
  registered to the first** and the first whose `IntersectRect` with the box is non-empty wins. **Rectangle picking,
  not pixel and not cell.** CONFIRMED. Structures whose template has `+0x64 != 0` and `+0x8c == 0` are transparent to
  the picker (they `continue`); other structures are hit (hit flag `0x20`, or `0x800` for `+0x8c` Usable).
- **Structure rects** (CONFIRMED `0x408068` flat, `0x4086b7` others, the cell scan of `FUN_00406f43`; [rendering](rendering.md#structure-pick-rects-and-dynamic-lights-confirmed-engine-drawlistpick_cell-lightspy)): per structure of the cell grid, registered when its visibility state `obj+0x7c` (`FUN_0041eb60`, **not** a death stage) is 0 (own structures always), **Flat templates included, destroyed ones included**: the record's `SelectionX1/Y1/X2/Y2` (`+0x20`) offset by `(x << 5, ((y + TileHeight - FullHeight) << 5) - ground)` (+0x40 / +0x44 cell). Registered once per box cell, the last copy (smallest x of the largest row of the box clipped to the window) orders it against units. Engine: `drawlist.structure_hoverable`, `pick_cell`, `DrawList.hover_picks` (`PickRect` entity = the structure id).
- **Hover brightness (CONFIRMED `FUN_004632a1` `0x463c87`)**: while `view+0x994 == this` and the modal cursor `client+0x3f4 == 0` the unit draw replaces its
  light-row argument by 0 (BRIGHT2 row 0 = x2, [lighting](../mechanics/lighting.md)); it reaches the sprite and its `b` overlay, not the shadows. Only the unit draw
  reads `view+0x994` (the byte search finds no other drawer, so **structures, objects and items are not highlighted**), the pointer on a hostile, neutral or
  friendly unit alike. Hovering also sets the object's redraw flag (`+0x114`). Engine: `build_draw_list(hover=)` -> `light_row=0` of that unit (only with `lit`).
- **Hover flags of structures (CONFIRMED `FUN_004180c6`)**: a structure that is not Usable and Indestructible is skipped; else flag `0x20`, plus `0x800` when `Usable`
  (`+0x8c`); `4` (hostile) comes from the owner's relation like for units; `0x40` (item cell) and `0x400` (fogged) come from the four tiles of the cell under the pointer
  (`0xc000` on all = visible), see [vision](vision.md). Cursor over a structure: hostile -> select (Alt move) even with Ctrl; friendly or neutral -> select, Ctrl attack,
  one hero selected and `Usable` -> town. Map 32's two hostile structures therefore only show `select` and the info panel. Engine: `window.cursor_input` reads
  `DrawList.hover_picks`, `hover_flags`, `fog.cell_visible` (tests/test_engine_hover.py).

## 8. Selection

- **Selection is a flag on each client object** (`obj+0x80`, setter `FUN_0046dd20`), not a list; the server stores
  none. `FUN_004167c2` recomputes `view+0x138` (first selected), `+0x140` (count), `+0x144` (bits above) after every
  change. No size limit on the client; an order packet carries at most 253 ids (`FUN_0050bbb8`). CONFIRMED.
- Mouse release (**CORRECTED**, [research §1.1](click-to-move-research.md): the release messages are `WM_LBUTTONUP`, view
  slot `+0x58` = `0x40c5d1`, and `WM_RBUTTONUP`, `0x40c53a`; `0x40e`/`0x40f` only toggle the inventory/spellbook) the left
  release always ends in `FUN_004175c7`: the rect between the press
  point (`0x604500 + 0x6c`) and the release point; **drag when its width or height exceeds `screenW * 10 / 640`**
  (10 / 12 / 16 px), else click. CONFIRMED.
  - Nothing selected, or the cursor is *select*: `FUN_00417986` (select). With a selection the other cursors
    issue orders instead (move 0x16, attack 0x19, 0x1a, 0x1b, 0x1d, 0x21, 0x24, spells 0x1e/0x1f): the dispatch
    table, the cursor-at-release rule and the pending-mode reset are in [research §1.2-§1.4](click-to-move-research.md);
    the minimap move order in §1.6 (H3).
- **Click select** (`FUN_00417986`): the topmost rect hit; if the object is **not a structure it is selected whatever
  its owner** (own, ally, neutral, enemy), after clearing the old selection. A structure hit leaves the selection alone.
  Selecting a foreign object is info-only (`view+0x144` bit 4 blocks orders). A click on empty ground with a selection
  is a move order (cursor *move*); with nothing selected it selects nothing. CONFIRMED.
- **Drag select**: every rect whose intersection with the drag rect has area > 10 px^2, **own** (`obj+0x14 == view+0x9cc`)
  non-structure objects only; if none qualifies the old selection is kept; otherwise it is replaced. CONFIRMED.
- **Shift**: click or drag *toggles* each own object; only while the selection is not foreign. CONFIRMED.
- **Left release, engine (H3 stage B)**: `OrderInput.is_order_click` (click, not a drag, non-empty selection) else the
  selection above; dispatch (R 1.2): move -> `MoveUnits`; attack over a non-unit -> `MoveUnits`; attack over a unit,
  swarm -> `Swarm` at the cell (also over a unit); patrol, defend, pickup, town, cast -> nothing yet; select -> the selection. Target cell `(mx >> 5) + camera
  cell x`, row `Projection.hover_cell` (the exe's `FUN_00417f31`), no fog / passability test; no cell (no row matches) =
  no order (DECISION: unreachable inside the view; the exe returns `H + 4`, R 1.6 CONFIRMED).
- **Right button, engine**: press sets nothing; mouse move with the button held scrolls the camera `delta/8` cells (`(d +
  ((d >> 31) & 7)) >> 3`, truncating, per MOUSEMOTION `rel`) and marks the drag; release without a drag cancels the
  pending mode, else `SelectUnits(())`; the command bar and info panel also take the release (`0x4adb09`, `0x4af0dc`).
- **Minimap, engine**: left press and every left move: inside the image with own units selected = `MoveUnits` to the

### 11.8 Engine notes (DECISION)
