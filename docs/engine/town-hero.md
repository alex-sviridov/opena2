# Town mode: the hero panels (the Inn window family, L3, mode bit `4`)

REA of the GOG `allods2.exe` (sha256 in [formats/README.md](../formats/README.md)). Marks: **CONFIRMED** (routine address given) / **INFERRED**.
Part of the L3 town spec ([design](../superpowers/specs/2026-11-13-l3-town-spec-design.md)); the shared core and the state machine are `town.md`; the shared message table is [town-worldmap 4](town-worldmap.md#4-messages-in-out) (`0x445`, `0x44c`, `0x442`, `0x468`, `0x42d` / `0x42e`), not repeated.
Single player only (`client+0x5d8 == 2`). Names of fields are ours; offsets and routines are the exe's.

**Result of the research (CONFIRMED, changes the design).** `FUN_0049a428`, `FUN_0049bd95` and `FUN_0049e187` are **not** three hero screens. They are the constructors of the **Inn window**, one class per town: base `0x49a428` (vtable `0x5ce5f0`, town 1 = human), `0x49bd95` (vtable `0x5ce680`, town 3 = druid, `inn_druid`), `0x49e187` (vtable `0x5ce798`, town 2 = Kaarg, `inn_kaarg`); each calls the base ctor `0x49a428` (`0x49bd95`, `0x49e187` are 7-instruction wrappers that only store their own vtable). The exe has **no separate hero / equipment screen in town**: the "hero" things of the town are (a) the Inn window's left stat panel (heroes and mercenaries), (b) the **unit info panel** (window 7, paper doll) that the town windows show at the bottom right, with the two hero arrows, and (c) the shop windows ([town-shop.md](town-shop.md)). The hire / dismiss / talk logic of the inn is already specified in [triggers 11.2](triggers.md#112-town-dialogue-enterinn-and-talkto); this doc owns the frame, the panels, the mode-bit table and the hero arrows, and leaves the dialogue words to `town-inn.md`.

## 1. Purpose and entry / exit

**What it is.** A full-screen (640x480 area) window of id `0x44c` with four visible parts ([2](#2-layout-per-resolution)): the stat sheet of one *person* (left), the inn scene with the NPC / quest presentation (centre), three buttons (top right) and the player's unit info panel (bottom right). A *person* is a hireable mercenary or a story NPC of the inn; the party's heroes are shown in the info panel and switched with the arrows.

**The window objects (CONFIRMED `FUN_00483129`, at start-up, `0x4837b2`-`0x483914`).** `client+0x104` = `0x49a428`, `client+0x108` = `0x49bd95` (allocation `0x16c`), `client+0x10c` = `0x49e187` (allocation `0x168`); all three are built with `id 0x44c` and the screen-centred 640x480 rect (`DAT_00621420 / 24 / 28 / 2c`, as the world map, [town-worldmap 2](town-worldmap.md#2-layout-per-resolution)). The town scenes are `client+0x110 / 0x114 / 0x118`, the shops `+0xf8 / +0xfc / +0x100`.

**Which town gets which window (CONFIRMED).** Everything is keyed by the **town id** (`GetCurrentLocation` object `+4`, `FUN_00473a30`; type is `+0`, [town-worldmap 5.1](town-worldmap.md#51-scenariodll-calls-ordinal-exe-pointer-loader-0x4818e7)):

| town id | scene (`0x48bbc0`, music) | inn (`0x48b885`) | shop (`0x48aea8`) | race strings |
|---|---|---|---|---|
| 1 | `+0x110` (`0x4ca23c`), `music\b14.wav` | `+0x104` (`0x49a428`) | `+0xf8` | human (`graphics\interface\inn\...`) |
| 2 | `+0x118` (`0x4d09ee`), `music\b16.wav` | `+0x10c` (`0x49e187`) | `+0x100` | Kaarg (`inn_kaarg`, `SFX\Town_kaarg`) |
| 3 | `+0x114` (`0x4ce2b9`), `music\b15.wav` | `+0x108` (`0x49bd95`) | `+0xfc` | druid (`inn_druid`, `SFX\Town_druid`) |

(The town 2 = Kaarg / town 3 = druid reading agrees with the tips `#tips11` "Ancient Woods ... Druid Shop and Inn" and `#tips12` "Kaarg" of `town.txt`. Outside the campaign (`+0x5d8 != 2`, multiplayer) the choice is by the message word instead: `0x43..0x45` -> `+0x104`, `0x63..0x65` -> `+0x10c`, `0x6f..0x71` -> `+0x108`, byte table `0x48bb91`: out of scope.)

**Entry (CONFIRMED).**
1. The scene's left-click handler (`0x4cace7`, hit test = vtable `+0x94` returning a region id) posts **`0x42b`** with wParam / lParam 0 for the inn region and `0x42a` for the shop region (human scene: region 1 = shop, 2 = inn, 8 = leave, table `0x4cae18` / `0x4cae04`; the other two scenes use the region flags 1 / 2 / 8, `0x4d06cc`-`0x4d07c7`: flag `2` = inn, `1` = shop, `8` = leave). It calls its own vtable `+0xac` first (plays the click). `0x40dd09` (in the client message loop `FUN_0040d9b2`) also posts `0x42b` with two words of a server message: the non-campaign path, not used here.
2. Client handler `0x4877f9` (table index of `0x42b`, [town-worldmap 1](town-worldmap.md#1-purpose-and-entry-exit)): **guard**: `client+0x404 == 0` (no screen bit at all, i.e. the town scene is up) **or** (`+0x5d8 <= 1` and `+0x404 == 1`). In the campaign a second click while any screen bit is set does nothing.
3. **`FUN_0048b885(msg, lparam)`** (the inn opener): releases the mouse manager's capture if held (`0x41e730` / `0x427501` / `0x48ad61`), wait cursor `0x626d20`; with `+0x5d8 == 2` the window is chosen by the table above; `AddChild(root client+0xcc, window)` (`FUN_004d3a64`); **campaign only (`0x48ba04`-`0x48baa6`)**: `EnterInn(&words, &count)` (Scenario ordinal 9, `[0x627480]`, [triggers 11.2](triggers.md#112-town-dialogue-enterinn-and-talkto)), the words into a local array, **`FUN_004f312a(server, Var(0x300), words)`** (builds one unit per word: the mercenaries / NPCs and the story heroes `0x15..0x1e`, [triggers 11.5](triggers.md)) and one pump of the client message loop `FUN_0040d9b2(0)` so that the client has the units (the else branch, `0x41a800`, is the non-campaign case). Then `FUN_004d4013(0x44c)` finds the window again (it stores `lparam` at `+0x138`), its vtable `+0x80` (**load**, below) runs, **`client+0x404 |= 4`** (`0x48bb13`), `FUN_004167c2` (the pack shown follows the selected hero), root redraw (`+0x34`), `client+0x44c := 0`, cursor `0x626cb8` (default).
4. **Load (vtable `+0x80` = `0x49abfe` base, `0x49c359` druid, `0x49e451` Kaarg; CONFIRMED `0x49e451`)** in order: `FUN_00437ee0` (flag `+0xa0 := 0`); `+0x68 := client+0xd0` (the view), `+0x6c := client+0xe0` (**the unit info panel, window 7**); the info panel is removed from its parent (`client+0xd4` `RemoveChild`), its rect is `OffsetRect(+(640 - width), 0)` (`FUN_00437bb0` = IAT `OffsetRect`) and it is added to the root (`0x49e4bf`-`0x49e53b`); **tips** (below); the person arrays (below); the hero list (below); `0x405` to the view (see 4), the selected hero `vtable +0x14(1)` (select) + `FUN_004167c2`, **`hero +0x1b8 |= 8`**; slot `+0x78` of the window's object (re-creates the three child panels, `0x49a65e`, [2](#2-layout-per-resolution)); the five taverner bitmap sequences of the race (`inn_kaarg\taverner\a1%04d.bmp` 15 frames from 1, `a2` 25 frames from 1, `a3` 3 from 1, `a4` 7 from 0, `a5` 29 from 0; the human / druid load their own `inn\candle`, `cauldron`, `tender\breath`, `tender\drink`, `inn_druid\waterdrop`, `taverner\a1..a3`); child inits `FUN_00496317` (buttons), `0x4970fe`, centre `+0x80`, `0x495e81` (left bitmaps), `0x497223`; slot `+0x88` (sounds, [6](#6-sounds-music-and-tips)); `+0x110 := 1` (loaded); the open sound `+0xa4`; ambient start `FUN_004a0ff0(+0x90)`; cursor wait -> default.

**Exit (CONFIRMED).**
- **ESC** (`WM_KEYDOWN 0x1b`, slot `+0x6c` = `0x49aae2`) and the third button ([3](#3-widgets-and-resources)) both call **`0x49b69b`**: the window sends itself **`0x445`** (slot `+0x48`; base `FUN_004dc2b0` unloads and posts **`0x44c`**) and, if `client+0x404 == 4` exactly, posts **`0x42e`** (handler `0x48637d` -> `FUN_0048bbc0`: the **town scene again**, with its music). No other exit: there is no cancel, no key other than ESC (every other key goes to the base `FUN_004dc326`).
- The `0x44c` handler `FUN_004891d8` (CONFIRMED, `0x4895b3`-`0x48962c`): window is `+0x104`, `+0x108` or `+0x10c` -> (`+0x5d8 != 2`: `FUN_004924cd`), **`client+0x404 &= ~4`**, `FUN_004167c2`. The campaign skips `0x4924cd`.
- The window **stays alive** (`client+0x104..` are never freed); every opening runs the load again.

**Entry / exit from the world map and the scenes (CONFIRMED).** The map never opens an inn ([town-worldmap 4](town-worldmap.md#4-messages-in-out)): the map ends in `0x468`, which builds the **scene** (`0x41aaa5(0,0)`, `0x48bbc0`); the scene posts `0x42b` (inn) / `0x42a` (shop) / `0x442` + `0x42d` (leave to the map, [town-worldmap 1](town-worldmap.md#1-purpose-and-entry-exit)). The inn returns to the scene with `0x42e`. The hero panels therefore sit between scene and scene: `scene -> 0x42b -> inn (bit 4) -> ESC / Exit -> 0x445 -> 0x44c (bit 4 cleared) -> 0x42e -> scene`.

## 2. Layout per resolution

The window rect is the screen-centred 640x480 area, origin `O = (fx, fy)`, `fx = (W - 640) / 2`, `fy = (H - 480) / 2` (as the map: 640x480 `O = (0,0)`, 800x600 `(80, 60)`, 1024x768 `(192, 144)`; CONFIRMED ctor rect). **All numbers are relative to `O`, screen pixels, no scaling.** What is painted outside the rect at 800x600 / 1024x768 is not this window's business (INFERRED black, [town-worldmap open question 3](town-worldmap.md#8-open-questions)).

**Three child panels (CONFIRMED `0x49a65e` for the base, `0x49bdca` / `0x49e1bc` pass the same rects):** ctor args are `(id, left, top, right, bottom, parent)`.

| panel | id | class ctor (size) | rect (relative to `O`) | content |
|---|---|---|---|---|
| left | `0x44d` | `0x494240` (`0x190`), vtable `0x5ce478` | `(0, 0, 160, 480)` | stat sheet + portrait of the person |
| right top | `0x44e` | `0x496076` (`0xc8`), vtable `0x5ce4f0` | `(480, 0, 640, 238)` | the three buttons |
| centre | `0x450` | base `0x497606` (`0x3cc`, human), druid `0x49ce4f` (`0x468`), Kaarg `0x49f353` (`0x4d0`) | `(160, 0, 480, 480)` | the inn scene, NPC, quest and reward presentation |

Add order (= draw order): left, right, centre (`FUN_004d3a64` at `0x49a6e9`-`0x49a70f`), plus a helper object at `+0x114` (`FUN_0052de35`, size `0x84`). The **unit info panel** (window 7) is the fourth part: it is created at `(0, 0xee, 160, 480)` (`0x483365`-`0x48337b`) and shifted by `OffsetRect(640 - 160, 0)`, so **(480, 238, 640, 480)** (the same 160x242 place as the mission layout at 640x480, [ui-layout 2](ui-layout.md#2-layout-per-resolution); INFERRED final value: the exe never reads the mission offset, see [8](#8-open-questions) 1). The window keeps `+0x68` = view, `+0x6c` = info panel.

**Left panel (`FUN_00494780` draw, `FUN_00494832` content; CONFIRMED).** Fields: panel `+0x5c` = the inn window. - bitmaps at the panel origin: `+0x168` at `(0, 0)` and `+0x16c` at `(0, 238)` (loaded by `0x495e81`: `graphics\Interface\Inn\LeftStats.bmp`, `LeftPicture.bmp`; which pointer is which is INFERRED by load order).

- **portrait**: a 160x240 surface blitted keyed (`+0x38`) from source `(0,0,0xa0,0xf0)` to `(11, 240)`; a person with `+0x1b8 & 0x11` (a hero / doll type) gets the paper doll baked to a temp file `%TEMP%\allods-2-<id>.$$$` through the unit's vtable `+0x88` (the doll builder, [paperdoll](../formats/paperdoll.md)); every other unit loads `graphics\infowindow\<type name><face if > 1>.bmp` (`FUN_004250f5`). With nobody: two centred lines `main.txt` `0x2f` and `0x30` at `(88, 54)` and `(88, 66)`, font1, table `0x620d90` (INFERRED the table: `FUN_0041f350`).
- below the portrait a caption block `(18, 50)` size 132x238 drawn by `FUN_0045d693` with `main.txt` entry `0x11c + k` (k from a kind switch over the person's word, `0x494832` `0x4948xx`): not decoded ([8](#8-open-questions) 5).

**Right panel (`FUN_004966aa` draw, mouse `0x496b1e` / `0x496b41` / `0x496bba`, hover `0x4971aa`, hit `0x497123`; CONFIRMED structure, button coordinates not extracted).** Background `graphics\interface\Inn\ButtonsArea.bmp`; three buttons `button1on/off`, `button2on/off`, `button3on/off.bmp` (hover on / off pair each, the press index `+0xc0`, the hovered one `+0xc4`), each with a caption string (`FUN_004018a0` from the interface text) drawn with font id `0xa`: the draw `+0x84` / `+0x8c` sprite loads and rect offsets `+0xa0` / `+0xa4` are per button. **Hero arrows (info panel, bottom right).** `ar1.bmp` at `(1, 0xcd)`, `ar2.bmp` at `(0x77, 0xcd)` of the info panel rect, 32x32: i.e. at `(481, 443)` and `(599, 443)` in the inn window ([ui-layout 11.1 / 11.10](ui-layout.md#1110-heads-panel-hero-arrows-and-the-extra-panel-window-6-heads-window-7-arrows-window-8-confirmed-unless-marked)).

## 3. Widgets and resources

**Class / vtable table (CONFIRMED).** The inn window (vtable `0x5ce5f0` base): slots `+0x2c` `0x49a8f3` (draw: `FUN_004dbd20` base draw if loaded `+0x110`, then **`FUN_004a0ff0(+0x90)`**: start the ambient sound `+0x90` unless it is already playing), `+0x30` `0x49a924` (empty), `+0x48` `0x49a931` (messages), `+0x4c` `0x49ab10` (mouse move: resets the button hover of the right panel when the pointer is outside it), `+0x6c` `0x49aae2` (key: ESC only), `+0x78` `0x49a65e` / `0x49bdca` / `0x49e1bc` (create the panels), `+0x80` load (`0x49abfe` / `0x49c359` / `0x49e451`), `+0x84` `0x49b41b` / `0x49cb27` / `0x49ecf7` (unload: frees the bitmaps / sprites), `+0x88` sounds (`0x49bb47` / `0x49c05f` / `0x49ef88`), `+0x8c` `0x49bc86` / `0x49c210` / `0x49f122` (frees the sounds, corrected in [town-inn 3](town-inn.md#3-sounds-of-the-three-classes-confirmed-paths-0x88-loads-0x8c-frees)). ## 4. Messages in / out

In: `0x402` tick; `0x414` / `0x415` arrows; `0x45a` tips Close; `0x445` (self-sent exit); keys: ESC only. Out (posted to the client / root): `0x42e` (back to the scene, only when the mask is exactly 4), `0x44c` (base unload, wParam = the window), `0x405` to the view (hero change), selection `vtable +0x14` of the unit, `FUN_004167c2`; shared: `0x42b` (in, from the scene), `0x42a` (shop). Everything else (`0x442`, `0x468`, `0x445` / `0x446`) is in [town-worldmap 4](town-worldmap.md#4-messages-in-out).

**Drag and drop (CONFIRMED by absence).** The inn window and its three panels have **no carried-item release handler**: slot `+0x58` of the window and the left panel is the default `0x437f10`, the right panel's `0x58` is the button release; the centre panel's `+0x5c` = `0x49a197` (hire). The carried-item handlers `0x4b4586`, `0x4b6399`, `0x4b80d3` ([ui-layout open questions](ui-layout.md#open-questions)) belong to the **shop** classes (`0x4b6bb2` / `0x4bde01` / `0x4c0017`). In the inn the only item motion is the info panel's own: pick up from the doll (`FUN_004af120`: left button held, nothing carried, picture mode, own-side single selected hero, hero bit) and the info panel's left release `FUN_004aebc8` / `FUN_004b028d(slot)` (equip rules [ui-layout 11.13](ui-layout.md#1113-backpack-window-bottom-bar-id-2-class-fun_004a2bba-vtable-0x5ce978-confirmed-unless-marked)); there is no pack target and no ground, so a carried item can only go back to a doll slot. Passing items between heroes is a **shop** feature (the tip `#tips4`: "drag any item on the table, then scroll to the character you want and take it back from the table again").

## 5. Data read / written

**Hero list (CONFIRMED `FUN_00472460`, global list object `0x6212d0`).** Rebuilt at every load: clear (`0x4738f0`), then every creature of the view list `view+0x9d0` in **list order = creation order** with `+0x14 ==` the viewer's player id (`view+0x9cc`): `+0x1b8 & 1` (hero) **and `+0x184 == 0`** (death stage 0: **dead heroes are skipped**) -> array A (`0x4738d0`, offset 0 of the object); else `+0x1b8 & 0x10` and `+0x184 == 0` -> array B (`0x473960`, offset `0x14`, counts the units with `& 2` in `+0x28 / +0x2c`; the second class, INFERRED the carried-over followers / companions). `0x4a0df0` copies A into the window's `+0xd4`; **`FUN_004725f0`** returns the index of the first A entry with `+0x1b8 & 0x20` (else `-1`) and becomes the shown hero `+0xbc`. So the party of the arrows is **the living heroes of the player in creation order** (for the campaign the carried roster, [campaign 1](campaign.md#1-api): `RosterEntry` order = the order `place_party` / the town build creates them; **the roster-to-unit step in town is not decoded**, [8](#8-open-questions) 3), starting on the unit that has bit `0x20` (INFERRED: the main hero; no writer of `0x20` found in this pass).

**Per-person data read.** The unit fields behind [ui-layout 11.1](ui-layout.md#111-unit-info-panel-window-7) (name, level, HP / mana, XP, attributes, damage, defence) through `FUN_0046aa1d`; the unit's type name and face for the portrait; `+0x1b8` bits (`1` hero, `2` mage, `4` female, `8` shown in the screen, `0x10` second class / doll builder, `0x20` current, `0x40` no text rows); `+0x1dc` the word id. Nothing is computed here: every displayed number is the unit's client field (the formulas live in [docs/data/progression.md](../data/progression.md) and the sim; the screen only formats).

**Written:** `hero +0x1b8 |= 8` at load; the selection (`vtable +0x14`); the `TalkTo` words by the buttons ([triggers 11.2](triggers.md#112-town-dialogue-enterinn-and-talkto)); the inn window's `+0xb8` / `+0xbc`; the info panel rect; **nothing about gold** (the hire is free), equipment (only the info panel, [4](#4-messages-in-out)).

**What the mission-time Heads panel / backpack lack versus this screen:** the person sheet (left panel), the hero arrows with the wrapping hero list, the buttons, the NPC / quest presentation; the mission Heads panel is only a picture ([ui-layout 11.10](ui-layout.md)); the backpack window is not shown at all (the pack is a shop feature).
